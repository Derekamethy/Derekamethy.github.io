01 / Flagship research · Tyndall

CRFID domain generalisation

Can a chipless RFID classifier recognise the same tag under an unseen reader geometry?

I re-examined the evaluation protocol and rebuilt testing around physical-condition groups, separating familiar-condition recognition from transfer to an unseen joint reader geometry.

Strict grouped evaluation12,600 spectra · 252 physical-condition blocks · unseen joint reader geometry

Transfer remained near chance. Signal, representation and readout diagnostics established what the tested methods could—and could not—generalise.

Methods, findings & scope

Experimental design

The existing campaign contains 12,600 spectra in 252 physical-condition blocks. I examined whether repeated sweeps or shared physical conditions could cross split boundaries and inflate apparent generalisation. In the grouped protocol, repeated sweeps stay together; a familiar-condition score does not establish unseen-geometry transfer. P1–P3 supply development data; P4 holds out the joint 150 mm / 45° geometry. Familiar-condition evaluation and target-labelled diagnostics answer separate questions.

Technical work

Signal preprocessing, a first-difference 1-D CNN, matched ERM/IRM/DANN experiments, source-selection analysis, linear probes and block/seed uncertainty estimates. GroupDRO supplies a further matched comparison. Domain-aware Mixup stopped at its pairing-feasibility gate before training; it has no performance score.

What the evidence supports

C1 achieved 15.66% accuracy (0.1566) and 0.1122 Macro-F1 at P4 across five seeds, against a 14.29% uniform-chance reference for seven classes. Tested source-only interventions did not establish reliable improvement over their matched controls. Probe results support a representation-transfer limitation, with seed uncertainty; they do not prove all tag information was lost.

Supporting work included external-dataset checks and an OpenEMS redesign study. The simulated improvement remained below its practical gate; no fabricated RF redesign or hardware classification improvement is claimed.

Scope: one acquisition campaign. My contribution is the ML pipeline, experimental evaluation and diagnostics on existing measurements. The figure’s GHz axis is nominal because exact sample-by-sample frequency coordinates are unavailable.

02 / Biomedical signal processing

EEG seizure detection

Turn multichannel scalp EEG into inspectable, patient-specific seizure events.

I implemented signal preprocessing, spectral and synchrony features, fold-local feature selection and a Random Forest pipeline, with event-level error analysis.

53 / 55 seizure events detectedReported retrospective study · 10 subjects · 580.57 hours

Retrospective within-subject study; the maintained implementation is recording-aware.

Pipeline, metrics & scope

From signal to event

CHB-MIT EDF recordings → 22 bipolar channels → 0.5–50 Hz filtering → 2 s epochs → 1,772 spectral, synchrony and temporal inputs → fold-local Top-30 selection → 500-tree Random Forest → temporal post-processing and event scoring.

03 / Digital signal processing

EEG multirate DSP

Reduce the sampling rate while protecting the useful EEG analysis band.

I designed an 8/125 rational conversion and Kaiser FIR, implemented a direct reference, and integrated SciPy’s polyphase resampler using the same coefficients.

500 → 32 Hz93.6% fewer samples · protected band: 0.5–12.5 Hz

Numerical and spectral validation on one 60 s recording; no clinical-performance claim.

Filter design, validation & scope

Design

L = 8, M = 125; a 4,145-tap Kaiser FIR at the 4 kHz intermediate rate. The 60 dB stopband target measured 59.89 dB on the validation grid. Eight-second windows give 0.125 Hz bin spacing; Hann-window spectral resolution is broader.

04 / Engineering prototype

Eight-channel EEG simulator

Make the signal source, device interface and verification path testable before hardware integration.

I built a Python desktop application for synthetic or recorded EEG, channel controls, timed playback, fault injection and virtual 16-bit DAC mapping.

8 channels · 3 verification levelsDesktop software and deterministic mock measurements

Software proof of concept designed for future MCU/DAC integration.

Signal chain & implementation boundary

Implemented software

Synthetic/NPZ and optional EDF input, monotonic-clock playback, channel selection and digital amplitude scaling. Virtual 16-bit codes represent a configurable ±200 µV target range. Mock device control, protocol tests and deterministic fault scenarios exercise the interface.

  1. EEG → desktop GUI → virtual DAC / mock deviceImplemented and exercised in software
  2. USB / serial adapter → MCU buffer, timer & DMASerial skeleton exists; waveform transfer and firmware remain to implement
  3. Multi-channel DAC → analogue scaling → µV output → EEG acquisitionProposed physical path; no measured hardware output

Verification

Separate simulator-output, acquisition and event-timing checks compare deterministic software references. Unit tests and CI cover waveform handling, DAC mapping, protocol behaviour and validation. These checks do not measure a physical acquisition device.

Demonstrates: signal-chain architecture, interface separation and verification planning for future hardware integration.
